Second-Look Lending

Predict each applicant's probability of default, turn it into an approve / deny decision that makes money, and give applicants with little credit history a fair second look.

This guide is for anyone joining the project: what it does, how it is built, how to run it, how to use every page, and where to start reading the code.

1. What this project is

A lender has a cost model: a repaid loan earns +$2,000, a default loses −$8,000, a denied applicant is $0. So approving only pays off when the probability of default (PD) is below 2,000 / (2,000 + 8,000) = 20%.

The catch is thin-file applicants: people with no credit-bureau history (30% of applicants). The model knows less about them, and in this data their risk falls over time, so a model trained on older weeks thinks they are riskier than they are. A flat 20% rule then turns away many who would have repaid. The project measures that unfairness (the inclusion gap) and fixes it without losing profit.

The dataset is synthetic — it mimics a real credit bureau's tables but contains no real people.

Lending always predicts the future from the past, so we split by week, never at random. Each window has one job, so nothing is judged on data it was tuned on.

5. How training works

Three algorithms, from simplest to strongest. Each one outputs a PD between 0 and 1.

ModelIdea in one line"Epochs"?
Logistic RegressionOne weight per feature, add them up, squash into a probability.max_iter: each solver iteration is one pass over all loans (stopped after 67).
Random ForestHundreds of independent decision trees on random samples, averaged.None — every tree is built once.
LightGBMTrees built one after another, each fixing the mistakes left by the previous ones.Boosting rounds: one tree per round, stopped early by validation AUC.

6. The decision policy

flowchart LR PD("Raw PD
from the model"):::ml subgraph OLD["Baseline (old way)"] direction LR B{"PD < 20%?"}:::decision A0(["Approve"]):::good R0(["Deny · many good
thin-file payers"]):::bad B -->|yes| A0 B -->|no| R0 end subgraph NEW["Second look (new way)"] direction LR C("Calibrate per segment
Platt scaling"):::ml DR("Drift correction
~0.008 log-odds / week"):::ml T{"Segment threshold
est 17.5% · thin 24.5%"}:::decision A(["Approve"]):::good R(["Deny"]):::bad C --> DR --> T T -->|below| A T -->|above| R end PD --> B PD --> C
  • Inclusion gap = among applicants who actually repaid, approval rate of established minus thin-file.
  • Inclusive Profit Score = profit − penalty × |gap|, counted only if the default rate of approved loans stays under 12%. Penalty: $100,000 per gap point per 100k applicants.
  • Thresholds are searched on weeks 86–91 (every pair from 5% to 50%) and the best score wins.

7. Setup guide

You need: Python 3.9+, Node.js 18+, git, and the dataset folder synth_home_credit (containing csv_files/ and solution.csv). No GPU, no accounts.

  1. Get the code 
    git clone https://github.com/Break-Through-Tech/American-Express-1C-second-look-lending.git
cd American-Express-1C-second-look-lending
  2. Add the dataset

    Put (or unzip) it at data/synth_home_credit/. That folder is git-ignored, so the data is never committed. If you keep it elsewhere, point to it instead:

    export SLL_DATA_DIR=/path/to/synth_home_credit
  3. Install and start the backend 
    cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
scripts/fix_lightgbm_macos.sh        # macOS only, if Homebrew's libomp is missing
.venv/bin/uvicorn app.main:app --port 8000 --reload

    Check it: http://localhost:8000/api/health should say "data_found": true. Interactive API docs: /docs.

  4. Install and start the frontend (second terminal) 
    cd frontend
npm install
npm run dev                          # open http://localhost:5173

    Or build once with npm run build and use http://localhost:8000 — FastAPI serves the built app.

  5. Train your first models

    On the Train page, train Logistic Regression, then Random Forest, then LightGBM. The first request builds the feature tables (about 20 seconds) and caches them. Each model takes 5–20 seconds; LightGBM with 20 Optuna trials about a minute.

Prefer the terminal? .venv/bin/python -m app.cli --model lightgbm --trials 20 trains a run without the UI. The notebook notebooks/second_look_lending.ipynb runs the whole project on free Colab.

8. How to use the app

Overview & EDA

/

Dataset size, default rates per segment, the weekly drift chart, a feature-vs-default explorer, table depths and missing values. Start here to understand the problem.

Insights: data & model

/insights · /insights?tab=model

Raw data: click any table to see 5 records, its columns and stats; follow one applicant from raw rows to one feature row. Model: the big-picture flow, the algorithm's training loop, its real first tree, how one prediction is built, and what decisions are worth.

Train models

/train

Pick a model, adjust settings (hover ⓘ for what each does), choose Optuna trials, press Start. The live panel shows each step, Optuna trials and the learning curve.

Compare models

/models

AUC, LogLoss and Brier for every run, split by segment. Choose on Validation; the test tab is a final check only. Click a run for details and feature importance.

Policy lab

/policy

Change calibration, drift correction, gap penalty and default-rate ceiling, or set thresholds by hand. See before / after profit and gap, profit and gap curves and calibration plots.

Score applicant

/applicant · /applicant?case=1000001

Look up any loan, see the baseline and second-look decisions side by side, try what-if changes, and read the SHAP reasons behind a LightGBM score.

Golden rule: make every choice (model, settings, policy) on validation. Look at the test numbers once, at the end. Picking by test score quietly turns the test set into training data.

9. Code walkthrough

The backend is plain Python functions with one-line comments; the frontend is plain React with one file per page. Read in this order:

  1. backend/app/config.py — paths, the cost model, the week split. 30 lines.
  2. backend/app/features.py — how 8 tables become 53 features. One small function per table.
  3. backend/app/models.py — PDModel wraps preprocessing and model for all three algorithms; fit() and predict_pd() are the core.
  4. backend/app/training.py — train() ties it together: split, tune, fit, score, save.
  5. backend/app/policy.py — the money maths: calibration, drift, profit, gap, threshold search.
  6. backend/app/main.py — every API route in one file; each route is a few lines.
  7. frontend/src/api.js then frontend/src/pages/ — every API call, then one page at a time.

Common changes

Add a feature

Add a column in features.py (inside the table's aggregation function, or in add_derived_features). Delete backend/artifacts/features/ or call POST /api/features/build, retrain, then run scripts/make_data_dictionary.py.

Add a model

Add it to MODEL_NAMES and DEFAULT_PARAMS in models.py, build it in build_model(), give it a search space in suggest_params() and help text in param_help.py. The UI picks it up automatically.

12. Glossary

PD
Probability of default: the model's estimate that a loan won't be repaid.
Thin-file
An applicant with no credit-bureau history.
AUC
How well the model ranks people: 0.5 is guessing, 1 is perfect.
LogLoss / Brier
How far PDs are from what happened. Lower is better.
Calibration
Whether a PD of 20% really means 20 in 100 default.
Drift
Data changing over time; here thin-file risk falls week by week.
Early stopping
Stop adding trees once validation stops improving.
Epoch
A full pass over the data. Not used by these models; see section 5.
Inclusion gap
Approval rate among repayers: established minus thin-file.
Out-of-time test
Later weeks the model never trained on, scored once at the end.
